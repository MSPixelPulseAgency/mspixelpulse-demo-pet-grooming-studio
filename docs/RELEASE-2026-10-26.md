# Stephy release — October 26, 2026

The owner explicitly approved completion, PR #9 merge and deployment to https://petgrooming.mspixelpulse.com/. The scope is this repository and its existing Vercel project only. Other projects, backend configuration, environment variables, customer data and appointments are excluded.

## Final refinements

- Mobile hero type is approximately 37.6–37.84px at 320–430px, with explicit two-line composition. Secondary headings scale down coherently. Photography and the opt-in film now appear before search on mobile, while desktop retains a balanced two-column composition.
- The floating liquid-glass header uses a smaller wordmark, restrained blur/transparency, an always-visible mobile enquiry link, bounded menu height, outside-pointer dismissal, Escape, Tab-out dismissal and automatic reset when entering desktop layout.
- Warm ivory, sage, lavender and a muted dark terracotta (#895441) form one shared palette. Card radii, borders, shadows, lift, spacing and touch targets are consistent. The new terracotta number badges were darkened and enlarged after contrast QA.
- The footer separates brand/social availability, route navigation, agency enquiries and unverified studio details. Instagram/Facebook silhouettes are non-interactive and explicitly labelled as awaiting verification. No fake social profiles, contact records, reviews or credentials are published. Future verified records can be supplied in src/data/site.js.
- Existing organic masks, photography layering, silent videos, gallery interactions, subtle parallax and scroll reveals remain. A short route-entry transition respects reduced-motion preferences and preserves focus/deep links. No new runtime animation/UI package is introduced.

## Form regression and safe preview behavior

The missing React error state is restored. ESLint’s recommended core rules are now merged correctly; the earlier configuration overwrote them. New DOM-level tests exercise the actual form, not only its transport helper.

The existing src/lib/mspInquiry.js is unchanged. Production retains the same intake URL, payload, consent, honeypot and backend-driven acceptance/error handling. Its browser preflight returns HTTP 204 for the production origin. No live enquiry, customer message or appointment was created during QA.

The backend continues rejecting unregistered preview origins with HTTP 403. Rather than spoof an allowed origin, add a proxy or broaden the backend allowlist, Vercel Preview builds now use a clearly labelled local rehearsal. The form validates locally and says “Preview checked. Nothing was sent.” It never calls the intake endpoint, stores details or claims backend acceptance. Production builds cannot accidentally inherit this mode: both Vite and pre-render compilation use the same non-secret VERCEL_ENV build flag, and the build checks assert the correct rendered submit behavior for each environment. No Vercel environment setting was changed.

## Validation

- Lint passes with the restored core recommended rules and hooks checks.
- Eight tests pass: four shared search/transport checks plus actual form validation/preselection, duplicate pending-submit protection, backend success/error/retry with local fetch mocks, and preview rehearsal with networking forbidden.
- Production and preview builds pass. Both pre-render all seven routes, and npm run check verifies media, route HTML, deployment configuration and environment-specific form behavior.
- Responsive browser matrix: seven routes × 320, 375, 430, 768, 1024, 1440 and 1920px. Checks include overflow, broken/missing-alt images, H1 count and a mobile heading-size limit.
- Automated WCAG A/AA checks run against settled pages at 1440px and 375px. This is an automated check, not full accessibility certification.
- Manual browser checks cover native invalid-form blocking, preselected package, search keyboard navigation/deep links/empty state, gallery filters and lightbox arrows/Escape/focus return, mobile navigation, and playback of all three silent films.
- Existing npm audit findings remain: two moderate and six high, zero critical. No dependency-upgrade PR is included in this release. The only added dependency in this continuation is jsdom for development tests.
- Physical-device and full screen-reader testing, field Core Web Vitals and inbox delivery are not claimed. Mail delivery cannot be proven without sending a live message, which the owner excluded.

Media sources, contributors, modifications and Pexels licensing remain documented in [MEDIA-LICENSES.md](MEDIA-LICENSES.md).
